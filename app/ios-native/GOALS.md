# iOS 原生客户端目标

本文记录 `app/ios-native` 的产品范围和验收要求。实现状态与证据见 [VALIDATION.md](VALIDATION.md), 帧输出实验见 [FrameLab](FrameLab/README.md)。未通过关卡的构建属于开发版。

## 使用与技术范围

- 个人使用, 不向上游提交或公开分发。
- 最低 iOS 26, 目标设备为 iPhone 16 Pro 及更新机型。
- SwiftUI 原生界面, 复用 Kotlin 数据源、弹幕接口与仓库层, 通过 SKIE 桥接。
- 播放与画中画均使用 mpv; 可以维护 MPVKit 补丁。AVPlayer 不能替代 mpv 完成画中画验收。
- 所有媒体处理在手机完成, 不依赖服务器转码或代理。
- 上游基于 `v6.4.0`, 按实际需要升级。MPVKit 固定为 `1.1.0-n9.0.2`。
- CI 在 macOS 编译、测试与归档; 播放、功耗和后台行为需要目标 iPhone 实测。IPA 使用个人 Apple ID 重签安装。

## 首版范围

| 能力 | 验收要求 |
| --- | --- |
| 追番、详情、搜索 | 原生界面, 复用上游数据层 |
| 在线源与 Jellyfin | 查询、解析、播放与切源流程完整 |
| 弹幕 | 只读, 支持来源过滤、样式与暂停恢复 |
| 进度 | 本地保存、Bangumi 进度与看过标记, 切集和退出不串集 |
| BT | 在手机上边下边播, 接通本地下载器与媒体读取 |
| 画中画 | mpv 解码输出接入系统画中画, 覆盖支持的容器、编码、字幕与音轨; 验证暂停、恢复、跳转、后台及音画同步 |
| AirPlay | 在线、BT、MKV 等输入直接投送, 转封装或必要处理在手机完成; 屏幕镜像不计通过 |
| 4K HDR / Dolby Vision | 保留位深、色彩和所需动态元数据; 按 Profile 与变体验证必要的 BL/EL/RPU, 不静默降为 HDR10 或 SDR |

系统挂起应用时允许 BT 和转码暂停。AirPlay 在缺少接收端时可以保留为实验能力, 但不能据此标记首版通过。全格式画中画、直接 AirPlay 或 HDR/DV 保真不可行时, 对应能力与完整首版保持阻塞, 不通过缩小目标解除阻塞。

已有的一起看、评论、缓存管理、手动查找、OP/ED 跳过和画质增强保留, 作为相关改动的回归项。

## 实施顺序与关卡

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| 1. 播放可靠性 | 会话生命周期、原生线程、进度、请求头、弹幕、音频中断和诊断 | 自动回归与目标设备连续操作验证 |
| 2. 画中画 / DV 可行性 | mpv 帧输出、系统 sample-buffer 显示、时间轴、高位深和元数据链路 | 实际缓冲区测试, Profile 样本核对与真机画中画; SDR 实验不替代 HDR/DV 验收 |
| 3. BT 接入 | 本地引擎、按需读取、边下边播、取消和缓存 | 合法测试种子的下载、seek、重缓冲与退出回归 |
| 4. 直接 AirPlay | 手机供流与转封装管线、路由和接收端适配 | 真实接收端播放与 HDR/DV 保真证据; 无接收端时保持实验状态 |
| 5. 性能与交付 | 首帧、seek、内存、掉帧、温度、电量和长时运行 | 相同设备与样本的前后对比, 所有首版关卡通过 |

阶段 2 的实验可以产出独立可安装验证工具; 只有具备能力和证据的路径才接入主客户端。编译成功、模拟器测试、真机播放、接收端播放和格式保真分别记录, 不相互替代。

## 签名约束

使用免费 Apple ID 时通常需要每 7 天重签, 同一设备安装的此类应用数量受限。远程推送、iCloud 等能力不作为本项目依赖。签名与实际系统权限以 Apple 当前规则和设备结果为准。
