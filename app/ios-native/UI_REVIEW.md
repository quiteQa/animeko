# 原生 iOS 界面评估与优化建议

评估范围: 播放页的竖屏与全屏截图, 以及探索、追番、条目详情、播放器和设置页的 SwiftUI 源码。截图能够支持播放页的视觉判断; 其他页面的实际渲染、深色模式和辅助功能仍需设备验收。本文的视觉方案用于设计评审。

## 整体判断

界面具备清楚的原生基础: 系统字体与图标、蓝色交互强调、圆角封面、分组背景, 以及独立滚动的内容区。适合沿用这套基础, 统一层级和组件规则。

| 维度 | 判断与依据 | 优化方向 |
| --- | --- | --- |
| 原生感 | 较好。设置使用 Form, 探索和追番使用系统导航、分段选择和列表 | 保留系统导航与表单, 用语义颜色适配浅色、深色和对比度设置 |
| 风格统一性 | 中等。内容页以分组卡片为主, 全屏分布多组玻璃胶囊, 两类区域的控件密度差距明显 | 内容区域以实色承载信息; 玻璃主要用于浮在视频上的操作, 统一圆角、图标和点击范围 |
| 信息层级 | 主标题、当前集和分区清晰。评分等三个底色标签、来源卡片的大图标和选集描边同时吸引注意 | 标题与当前集优先, 降低元数据背景强度, 播放源与弹幕合并为一张两行卡片 |
| 观看体验 | 全屏竖向布局存在大量留黑, 系统状态栏与播放器状态行同时显示; 底栏动作挤压进度条 | 竖持显示顶部 16:9 视频与详情, 横屏专注视频; 状态栏由页面统一控制; 全屏进度与动作分为两行 |
| 品牌辨识度 | 偏弱。通用系统样式占比高, 封面是主要辨识元素 | 使用统一的蓝色、封面比例和“正在播放”标记形成识别, 避免加入额外装饰色或渐变 |
| 无障碍与适应性 | 源码普遍使用语义字体和颜色, 部分播放器按钮高度为 34–40pt, 探索固定三列 | 点击区域至少 44×44pt; 大字体时减少列数、让标题换行; 实测 VoiceOver、增强对比度和减少动态效果 |

全屏竖屏残留与操作失效属于交互缺陷, 应作为发布关卡处理。

## 视觉规则建议

| 项目 | 建议规则 |
| --- | --- |
| 色彩 | 交互与选中态使用同一强调蓝; 正文、次要文本、背景使用系统语义色。评分星、警告和错误使用语义色 |
| 字号 | 番剧标题 `title2` / semibold; 分区标题 `headline`; 正文 `body` / `subheadline`; 元数据 `caption`。时间与百分比使用等宽数字 |
| 间距 | 页面水平边距 16pt, 卡片内边距 12–16pt, 同组元素 8–12pt, 区块间距 24pt |
| 圆角 | 内容卡片 16pt, 缩略图 12pt; 胶囊用于简短状态与悬浮操作, 避免所有内容都套胶囊 |
| 封面 | 竖版封面保持统一比例; 剧集缩略图 16:9; 选中集用细蓝边与播放标记, 兼顾非颜色识别 |
| 文案 | 一级信息说明“是什么”; 次级信息说明清晰度、字幕和状态。可操作位置显示明确的“切换”“全部”等动作 |
| 对比度 | 普通正文以 4.5:1、大号文字及关键图形以 3:1 为目标; 对实际渲染采样验证, 避免用低透明度白字叠浅色视频 |

## 页面优化优先级

### P0: 播放交互

- 方向与全屏由同一状态持有; 退出时同步释放全屏触摸层与视频所有权。
- 竖持恢复详情与评论布局, 保持同一播放会话、进度与音轨。
- 横屏仅显示一套状态信息, 页面负责系统状态栏的隐藏与恢复。
- 左侧纵向拖动调整亮度, 右侧调整系统媒体音量; 手势避开顶部操作区、底部进度和屏幕边缘。锁定时禁用调整。
- 反馈展示图标、数值与进度, 松手后短暂保留。离开播放页恢复手势调节前的屏幕亮度; 系统音量保留用户设置。

### P1: 播放页视觉

- 播放源和弹幕组成一张卡片, 使用内部细分隔线。两行共用字体、图标尺寸、左右边距和触摸高度。
- 评分、开播时间、集数使用轻量元数据行, 把“在看”和当前集保留为主要状态强调。
- 全屏底部采用两行: 进度条与时间一行, 上一集/播放/下一集及次要动作一行。截图、填充、OP/ED 和统计可通过更多菜单访问。
- 播放器操作提供 44pt 触摸范围, 图形维持 18–22pt。画中画、音轨与字幕仍可直接找到。
- 浅色与深色保持同一布局, 深色页面使用中性深灰和同一强调蓝。

### P2: 全局一致性

- 探索的海报网格、详情页推荐与搜索结果共用封面组件和占位样式。大字体时允许网格降为两列。
- 追番页统一观看进度、播放下一集和收藏状态的字级与颜色; 播放按钮保留为明确的主要动作。
- 设置与账户页保留系统 Form/List, 分组标题、说明与错误提示遵循同一规则。
- 加载、空态、错误、下载完成和不可用按钮均使用统一组件与文案, 避免每个页面自行定义一套表现。

## 验收方式

- 在同一设备反复横屏/竖屏与手动退出至少 20 次, 检查暂停、拖动进度、选源、评论及返回都可操作。
- 锁定时旋转手机, 检查不退出; 解锁与手动退出均有确定结果。iPad 的窗口调整单独验证。
- 对左右手势检查方向、数值范围、取消和页面切换; 用物理设备确认系统音量实际变化、亮度退出恢复及蓝牙/AirPlay 音量可用性。
- 在紧凑屏幕、横屏、深色模式和辅助功能大字体下比较同一组页面。大字体不得覆盖动作, 手势不得截获进度与按钮。
- 使用同一视频在浅色/深色场景检视浮层可读性; 减少透明度与减少动态效果开启时检查操作反馈。

自动验证入口包括 `App/Tests/PlayerInteractionTests.swift` 的策略回归和 `PlayerUITests` 的视口/触摸模拟器测试。后者复用生产视口与手势层, 使用无网络的播放桩; 完整解码、真实设备旋转与外部音频路由分别验收。
